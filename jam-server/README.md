# Сервер джемов SoundCloud 2

Cloudflare Worker и по одному Durable Object на комнату. Хранит только то, что нужно комнате: имена участников, ссылки на
треки, очередь и позицию. Ни аккаунтов, ни токенов SoundCloud сервер не видит. Комната стирается через 6 часов без активности.

Протокол и логика комнаты лежат в клиенте (`src/services/jam/protocol.ts`, `room.ts`, `sync.ts`); этот сервер импортирует их
оттуда, поэтому развёртывать его нужно из полного клона репозитория, а не из одной папки `jam-server`.

## Развернуть

Нужен бесплатный аккаунт Cloudflare и Node.js.

1. Открой терминал в папке `jam-server`.
2. `npm install`
3. `npx wrangler login` (откроется браузер, войди в Cloudflare и разреши доступ).
4. `npx wrangler deploy`
5. В конце вывода будет адрес вида `https://sc2-jam.<твой-поддомен>.workers.dev`. Скопируй его.

## Куда вписать адрес

Один из двух способов:

- В клиенте: F1, раздел «Дополнительно», поле «Сервер джемов», вставить адрес. Работает сразу, перезапуск не нужен.
- В сборке: открыть `src/ipc/jamIpc.ts`, вписать адрес в `JAM_SERVER_DEFAULT`, пересобрать клиент. Тогда у всех, кто его установит,
  джемы работают без настройки; поле в F1 остаётся для смены адреса.

Проверка: открой на сайте Ctrl+Shift+J, нажми «Создать джем». Появится код из шести знаков; друг вводит его в том же окне.

## Локальная проверка

`npm run dev` поднимает сервер на `http://localhost:8787`. Такой адрес (только http и только localhost) клиент принимает в
поле «Сервер джемов».

## Протокол

JSON по WebSocket. Создание комнаты: `POST /rooms` возвращает `{code, hostToken}`. Подключение:
`GET /rooms/КОД/ws?name=…&avatar=…&token=…` (token нужен только хозяину и возвращает ему права после обрыва связи).
Все сообщения описаны типами в `src/services/jam/protocol.ts`. Лимиты: имя до 32 знаков, очередь до 200 треков, сообщение
до 8 КБ, до 50 участников, 30 сообщений за 10 секунд с одного соединения.

Если хозяин вышел, хозяином становится самый давний из оставшихся.
